# MotusCap Lite — Context

Lite is a desktop/laptop operator app for **synchronous multi-phone video + optional IMU recording**, then **per-camera 2D / single-view 3D pose** (MediaPipe on the desktop). It is **not** MotusCap: no space calibration, no multi-camera triangulation, no fused scene.

**Repo:** [JustinClc/MotusCap-Lite](https://github.com/JustinClc/MotusCap-Lite) (private). MotusCap is **reference only** for device pairing.

**UI source of truth:** Open Design demo at `~/Documents/MotusCap-Lite-OpenDesign/`.

**Platform / deliverable:** desktop software app on **Electron** (same shape as MotusCap: shell + local backend). **Windows `.exe` installer is primary.** **macOS is lower priority** (still planned; not blocking the first Windows ship). Phones remain browser/PWA cameras.

## Glossary

| Term                        | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Device Pairing**          | QR on desktop → phone PWA completes pairing → `device_id` + token. One QR pairs **one** camera.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **Camera switch**           | On the phone, after pairing: pick another of the phone's cameras (front, back, ultra-wide…) without re-pairing. Same slot, token and view. Locked from a trial's countdown until its upload finishes, and while a photo is sending. The desktop shows the new camera name.                                                                                                                                                                                                                                                                                                                                                                                               |
| **Frontal (F)**             | Cam 1 view role. Required for standing posture. A **single** camera sits in front of the subject and uses **no** view suffix in filenames.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **Lateral (L)**             | Cam 2. Fixed on the subject's **right**. File suffix `_L`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **Additional / Others (O)** | Cam 3. Any angle; at most one O (max 3 cameras). Suffix `_O`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **Preview**                 | Low-res frames streamed to the desktop for live MediaPipe overlay during Capture. Operator can turn **live preview off** on Capture (during recording too); that only stops preview traffic, not the recorded trial video. It applies to Capture only and turns back on when Capture closes; Pair and Standing always get previews.                                                                                                                                                                                                                                                                                                                                      |
| **Full-res**                | Phone-recorded `.mp4` uploaded after a trial. On **Capture**, trial recording quality is operator-selectable (**Auto**, **1080p**, **720p**, **480p**); Auto picks the highest rung that holds 30 fps on every phone (or, when none can, the highest rung with the best fps); **Refresh** re-probes every phone. Quality and Refresh are locked from Start until Stop; phones apply a new preset only between takes, never mid-recording, and do not probe while recording or uploading. **Standing posture stills** stay max-res and are **not** tied to these presets. Pose **re-runs** MediaPipe on trial full-res. Save/Export = **original** media (no 2D overlay). |
| **Standing posture**        | Three captures on the **frontal** camera only: F → LL → RL. Desktop MediaPipe gate (landmarks inside the 1 : 2.2 guide frame) → 3 s countdown → full-res still → review (**Proceed** / **Retake**). Saves the guide-frame crop plus the uncropped `_full` original. After the third, prompt the subject to **face the frontal camera again** before Capture. Recording-quality presets on Capture do **not** change standing still capture.                                                                                                                                                                                                                              |
| **Near-side check**         | Side postures: check only landmarks facing the camera; name the missing part.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **Shared start**            | Desktop start signal; ≤ **5 frames** offset OK.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **Trial**                   | Max **3 minutes**. Multiple trials per session kept; Pose/Review have a **trial picker**.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **IMU (UI this phase)**     | Up to 4 optional: Femur L/R, Tibia L/R. Any subset OK. When backend exists, **one CSV** with all connected sensors' channels. Backend deferred.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

## Operator flow (six steps)

1. New Session
2. Pair (1–3 cameras; optional IMU UI)
3. Subject & standing posture (Subject ID required; load existing retakes postures)
4. Capture (≤3 min; **Auto / 1080 / 720 / 480** trial recording; optional live 2D pose from preview MediaPipe; preview can be disabled)
5. Synced review (trial picker; Record another / Proceed to pose reconstruction)
6. Pose (per-camera 2D+3D; re-run on full-res; MediaPipe units; trial picker)

## File naming (Save)

Pattern: `[subjectID]_[subject-name]_[recording]_[view]` with **spaces → hyphens** in the subject name.

| Asset            | Example                                                                                                                                                                                                                                                                                                                                                               |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Multi-cam video  | `UG0001_Chan-Tai-Man_gait01_F.mp4`, `…_L.mp4`, `…_O.mp4`                                                                                                                                                                                                                                                                                                              |
| Single-cam video | `UG0001_Chan-Tai-Man_gait01.mp4` (**no** view suffix)                                                                                                                                                                                                                                                                                                                 |
| Posture PNGs     | In the subject folder: `…_standing_F.png`, `…_standing_LL.png`, `…_standing_RL.png` (cropped) + `…_standing_*_full.png`, plus `…_subject.csv` (`subject_id`, `display_name`, `height_cm`, `weight_kg`). Written by **Save Subject & continue**. Selecting an existing folder writes into that folder. Creating a new one writes into `<parent>/<subject id>_<name>/`. |
| Trial videos     | Inside that subject folder’s `<trial>/` subfolder. The trial folder is the trial name with spaces → hyphens. Example: `gait01/UG0001_Chan-Tai-Man_gait01_F.mp4`.                                                                                                                                                                                                      |
| IMU CSV (later)  | `…_IMU.csv` — timestamp first column, then all connected sensors' channels (e.g. `FemurL_ax` … `TibiaR_gz`). Naming helpers exist in `src/lib/imu.ts` + `imuCsvFileName`; **write deferred**.                                                                                                                                                                         |
| 2D landmarks     | `…_pose2d.csv` — one row per frame. `Frame`, `FPS`, then `_x`, `_y`, `_p` for shoulders, hips, knees, ankles, foot index, then nose, eyes, ears, elbows, wrists, heels. x/y are normalized 0–1. `VideoWidth` and `VideoHeight` are the last columns (pixels = x × width).                                                                                             |
| 3D landmarks     | `…_pose3d.csv` — same layout plus a `_z` block. Raw MediaPipe metres, hip-centred, y down.                                                                                                                                                                                                                                                                            |
| OpenSim TRC      | `…_pose3d.trc` — metres, Y up (`Y = -y`, `Z = -z`). Marker names match Pose2Sim `Markers_Mediapipe.xml` (`LShoulder`, `LBigToe`, …). Ears are left out. Hips stay at the origin, so inverse kinematics recovers joint angles. Pelvis translation is absent.                                                                                                           |

**Save Subject & continue** (Subject page, after F, LL, and RL) opens a choice: select an existing subject folder, or create a new one under a parent directory. Selecting an existing folder writes the six PNGs and `…_subject.csv` directly into it. Creating a new one writes them into `<parent>/<subject id>_<name>/`. Cancelling the choice stays on the page. It asks again after a retake. A missing cropped still is not replaced with a placeholder, and Continue does not proceed until the files are written.

**Save** on Pose writes that trial’s original videos into `<subject folder>/<trial>/`. It reuses the subject folder from Save Subject & continue. Landmark export uses the same trial subfolder. Non-ASCII (e.g. Chinese) in names: **keep as typed**; only spaces → hyphens.

2D and 3D exports are per camera (this view, or one file per view). JSON (`…_pose.json`) keeps all 33 raw landmarks plus `video_width` and `video_height`. Scale-to-height is view-only.

## MotusCap reference (adapt, don't fork)

- Phone: `apps/pwa` ProductionApp / PairingPanel / recording, trialUpload, preview libs
- Backend: device_pairing / pwa/pairing
- Desktop: Electron + supervised local backend (`apps/desktop`)

## Out of scope (v1)

- IMU fusion into pose
- Tablet operator app
- IMU pairing/recording/playback **backend** (later module)
